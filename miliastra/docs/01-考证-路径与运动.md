# 官方文档考证 01 · 路径与运动

> 来源：GitHub 上 Miliastra-knowledge 的官方文档镜像（社区整理的官方文档 Markdown 资产库）。
> 抓取时间：本次移植工作开始时。5 个目标 URL 全部 200，无需 API 回退。
> 补抓：`mhnmcmipncrg`《基础运动器》、`mhciimiw86jg`《本地投射物》。

## 0. 结论先行（这三条会直接改变移植方案）

1. **"物体沿预设轨道前进"只能用基础运动器的「路径运动器 / 关卡路径运动器」** ——
   不是《操控运动器》（那个是玩家输入驱动的）。
2. **路径是"路点折线"，速度是"逐段到达时长"，没有 m/s，也没有弧长/进度参数。**
3. **文档里没有任何"读取物体在路径上的进度"的节点。** 全文检索 4 份《查询节点》
   与 2 份《其它节点》中的"路径/路点/进度/插值"——**零命中**。

> ⚠ 对本项目的意义：本作的珠串模型（`wp` 弧长、绳模型推动、空隙、后退冲量）
> **无法照搬**——平台不暴露弧长，也不让脚本查询进度。移植时必须换一套模型。

## 1. 路径的数据模型（《路径》mh333vim2h44）

- 原文定义：「路径是将一至多个只包含位置和旋转信息的**路点**，汇总为一组路径信息的功能。」
  -> **逐点折线**，每点只有位置+旋转，**没有样条控制柄/权重**。
  （编辑辅助里有"指向终点方向切线""指向起点方向切线"，但那是改写**路点旋转**的按钮。）
- 坐标系：「路径中的路点信息为**世界坐标和旋转**，不会因为被引用而被调整数据内容。」
- 共用：「路径可被任意支持功能所引用，目前包括**造物**的**未入战-巡逻**功能、
  基础运动器组件的**关卡路径运动**。」配置栏有"造物引用/物件引用：显示该路径被引用次数，
  可定位引用该路径的造物/物件" -> **一条路径可被多个物体共用** ✓
- 进度参数：**不存在**。全部参数只有：名称、索引、锁定变换、是否在场景中显示、
  路径中心点位置/旋转、路点列表（位置/旋转）、添加/自由放置/复制/粘贴/删除。
- 资产性：「通过【创建路径】可以新建路径」；「**索引**：路径的唯一标识，**可用作节点图入参**」；
  入口在"左上角系统菜单 -> **路径管理**" -> 编辑器内资产；
  **运行时可创建/修改路径：文档未提**（节点图侧看起来只有只读的"获取"）。

## 2. 挂到路径上：基础运动器（mhnmcmipncrg）

先排除误解：《操控运动器》(mh1ytk9631fm) 讲的是"运行时通过轮盘输入操控元件/实体移动、施放技能"，
且「操控运动器和其他类型的运动器**互斥**」；它的速度参数（前进加速度、最大前进速度、
后退加速度、阻力减速度）**全部由玩家输入驱动**，不能自动沿路径走。

基础运动器里相关的两类：

- **路径运动器**：「描述让物体沿指定路径运动的运动器，路径通过有序的多个路径点连接组成。」
  路点参数含「**到达时长**：从上一个点到当前点所需要的时长」「**相对位置**：路径点相对于实体的位置」。
- **关卡路径运动器**：「引用一条**路径管理**工具内的关卡路径，在开始运动时，物件会先以配置的
  方式前往路径的第一个点，之后再沿路径运动」；「**关卡路径**：引用的路径，在选择一个路径后，
  会根据路径管理中的路点配置自动生成路点信息」；「显示路点信息：开启后显示路点的详细数据，
  但在运动器内无法更改」。

速度：「路径段上**没有 m/s 参数，只有逐段『到达时长』**」；
只有"前往路点 1"用速率——「抵达方式　固定速率 / **运动速率（m/s）**」或「固定时间 / **运动时长（s）**」。
**是否匀速取决于时长与段长的关系，文档未承诺匀化。**

暂停/后退：
- 状态章节：「**暂停中**：…区别于停止，暂停中的运动器会**记录当前的运动进度**，并在恢复后继续运动」
- 节点图节点：「激活基础运动器」「创建运动器」「暂停基础运动器」「恢复基础运动器」「停止并删除基础运动器」
- **没有反向/倒退节点**；换向只能靠「**循环类型**：单程 / **往返** / 循环（到达终点后瞬移回起点重新开始）」

叠加：「路径运动器和关卡路径运动器**不可叠加**」；表格显示关卡路径运动与匀速旋转、
朝向目标旋转、路径运动、定点运动**均不可叠加**；同名运动器冲突时「会**先停止**（而非暂停）已存在的运动器」。

教程《2.4 基础运动》印证：运动类型选"路径运动"、【路点】配运动位置与运动时间、
【循环类型】循环、【初始生效】，节点图用【激活基础运动器】，
并可用"施放时停技能使物体暂停运动"。

## 3. 投射运动器（mhaqt9rgqv4u）

- 四种类型：**直线投射**（初始速度=方向、速率、加速率、加速时长、贴地运动）、
  **抛物线投射**（初始速度、速率、重力加速度）、**追踪投射**（追踪对象/挂接点、追踪角速度、
  追踪最后阶段：无/停止追踪/吸附追踪）、**圆周投射**（围绕对象、半径、角速度、是否顺时针）。
- 限制原文：「投射运动器组件上**同时只能生效一个**投射运动器」；
  「投射运动器的位置**在各端可能会有差异**，因此被推荐用于做投射物，或表现性质的运动」；
  「发生**断线重连**时，投射运动器的位置可能会被**重置**」。
- 《本地投射物》(mhciimiw86jg)：「本地投射物实体运行时，依赖**投射运动器**决定其运行时的规则，
  依赖**命中检测**决定其碰撞触发的判定规则和效果」、「遵循『生命周期』的配置」——
  永久持续 / 持续时长、X/Z 轴销毁距离、Y 轴销毁距离、生命周期结束时按序执行能力单元；
  且「本地投射物需要**在编辑时预先定义**，才能被技能节点图引用创建」。

## 4. 物体之间的相对位置与排布

- **读进度**：文档中没有任何"获取物体在路径上的进度"节点。
  路径文档的节点图部分只有**「获取指定路径点信息」**（参数未爬到）。
  另外全文检索 4 份《查询节点》(mh1w3z96rpne / mh2crq9jzueq / mh65asiyhv2k) 与
  两份《其它节点》(mh84c29jwjgy / mhbbdr09w60g) 中的"路径/路点/进度/插值"——**零命中**。
- **固定间距排 N 个球**：文档**没有**间距/相位偏移参数。能用的原语组合只有三条：
  1. 路径可被多个物件引用（引用计数可查）；
  2. 每个物件各自挂关卡路径运动器，**对同一路点各填不同的"到达时长"**；
  3. 《数据复制粘贴》(mh6fj30p2cmo) 可把整个元件/实体的配置复制到同类目标 ——
     「除名称、元件ID、归属页签外的所有数据」「数据替换后**标识码不发生变更，
     不影响节点图逻辑的引用**」-> 便于批量造球。

## 5. 文档没说的（必须进游戏实测）

1. 是否存在"读/写路径进度(0~1 或弧长)"的节点（含「获取指定路径点信息」的真实参数）。
2. 路径运动器相邻段的"到达时长"是否按弧长匀化、段间速度是否连续。
3. 同一路径被 N 个物件同时引用时是否各自独立计时、能否设置初始相位错开。
4. **运行时能否新建/修改路径**（节点图侧似乎只有只读"获取"）。
5. 暂停→恢复是否精确续算；除"往返"外有无倒退播放。
6. 球同时要"沿轨道前进 + 参与碰撞判定"时，投射运动器与基础运动器的取舍。
7. "索引可用作节点图入参"的具体节点清单与用法。
8. 数据复制粘贴批量生成的球，其关卡路径运动器是否仍指向同一路径、是否需逐个重填到达时长。
