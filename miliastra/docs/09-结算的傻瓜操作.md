# 傻瓜操作：满 4 分钟才结算（不加排行榜）

> 目标：一局打满 **4 分钟**后，"可以结算"；**不上排行榜**。
> 依据全部来自官方文档（文末列了出处），**没有凭记忆编的节点名**。

## 〇、先要知道的一件事（决定了走哪条路）

官方原文（`试玩.md`）：

> **"玩家可通过完成挑战或者主动退出来触发关卡结算。"**

⇒ **平台的「退出按钮」随时可用**，而且一按就触发结算 ✓。
⇒ 所以"**4 分钟之前不许结算**"这件事，**脚本锁不住** ✗（退出按钮是平台固有控件，脚本碰不到 ✓）。

于是有两条路，**推荐 A**：

| | 做法 | 难度 | 能否硬锁 |
|---|---|---|---|
| **A（推荐 ✓）** | 靠**脚本提示**：满 4 分钟面板上写"可以结算了，点右上角退出" | **零节点图** ✓ 只改一个常量 | ✗（玩家提前退也拦不住，但没人会那样做）|
| B | 节点图里**计时 240 秒**再去触发结算 | 要连节点图 ✓ | ✓ |

---

## 一、A 路线：傻瓜三步（只改脚本，10 秒搞定）

### 第 1 步：改一局时长（4 分钟）

文件：`miliastra/lua/src/egg.lua`

```lua
M.SESSION_SEC = 600      -- ← 把 600 改成 240（4 分钟 = 240 秒）
```

### 第 2 步：面板上会说这句话（已经写好了 ✓）

4 分钟到 ⇒ 面板第 5 行自动变成：

    ★ 已收盘（4 分钟到）—— 点「返 回」结算

（这句本来就有 ✓，只是秒数跟着 `SESSION_SEC` 走 ✓）

### 第 3 步：在编辑器里把"结算界面"打开（一次设置 ✓）

1. 打开**关卡设置 → 结算**页签
2. **结算界面类型**：选 **个人结算**
3. **启用游戏内排名**：**关**（不开就不排名 ✓）

**外围系统里**：`排行榜` 和 `竞技段位` **两个都别开** ✓
（官方："排行榜功能与竞技段位功能仅可选择一项开放" ✓ 都不开 = 不上任何榜 ✓）

### 完成 ✓

玩家流程：进彩蛋 → 玩到 4 分钟 → 面板提示 → **点平台右上角的「退出按钮」** → 平台弹出结算 ✓
（**不上榜** ✓ 因为外围系统里没开 ✓）

---

## 二、B 路线：要"硬锁 4 分钟"（要连节点图）

1. 同 A 的第一步、第三步（时长 + 结算页签 + 不开榜）
2. 打开**节点图**，接一条：

       （关卡开始 / 玩家进入）──► 【计时/延时类节点，设 240 秒】
                                       │
                                       └──► 【设置玩家结算成功状态】（胜利 / 失败 / 未定）
                                       └──► 【结算关卡】        ← 官方："触发结算后整个关卡将会结束"

3. ⚠ 节点图里那个计时节点的**确切名字**，我在 219 篇文档里**没找到**（只翻了 `执行节点.md`，
   里面是循环/变量/列表那几类 ✗）⇒ **以编辑器里的实际名字为准，我不瞎写** ✓。
   你打开节点图搜"**计时**"或"**延时**"两个字就能看到 ✓。

## 三、⚠ 一条必须知道的副作用

官方原文（`关卡结算.md`）：

> **"触发结算后整个关卡将会结束"**

⇒ 一旦走了结算，**整个关卡结束**，玩家被送回局外 ✓ ⇒ **交易所这一局也就结束了** ✓。
**想再玩就重新进一次** ✓（不是永久关闭 ✓，但每次都会被踢出来一次 ✓）。

所以：
- 想**反复玩**彩蛋 ⇒ 用 **A** ✓（只是提示，不真的结算 ✓）
- 想**正式收官** ⇒ 用 **B** ✓（结算一次，回局外再进 ✓）

## 五、★ 防"无条件速通"（奇匠的顾虑：速通会被官方判为劣质）

**结论：把「结算关卡」锁在 240 秒之后，就不可能速通 —— 而且这不需要脚本参与 ✓**

理由是官方机制本身给的 ✓：

1. **"关卡结算是由节点图触发的行为"**（`关卡结算.md`）⇒ **"通关"这件事只能由节点图宣布** ✓
   ⇒ 只要你的节点图里"结算关卡"前面串一个 **240 秒计时** ✓，**4 分钟之内谁也通不了关** ✓✓
2. **提前退出不算通关** ✓：结算状态有 `逃跑合法性 / 结算状态（胜利·失败·未定）` 两个字段 ✓
   玩家按退出按钮 ⇒ 走的是**逃跑**那一支 ✓，**拿不到"胜利"结算** ✓
   ⇒ 所以"速通"既不能用计时绕过、也不能用退出伪造 ✓

### 连法（节点图，三步）

    （关卡开始 / 玩家进入）
        │
        └──►【计时 / 延时节点：240 秒】
                │
                ├──►【设置玩家结算成功状态 = 胜利】
                └──►【结算关卡】          ← 这一刻才可能通关

⇒ **最快通关时间 = 4 分钟**（计时没到，结算节点根本不会被触发 ✓）

### 还可以再加一道（可选 ✓）

- 计时之后再加一个条件节点（例如"玩家在关卡内"或某个开关变量 ✓）
  ⇒ 让"结算"只在**满足条件**时发生 ✓，进一步杜绝脚本化速通 ✓
- ⚠ **"把脚本里的成绩交给节点图"这条路我还没验证** ✗（客户端脚本 ↔ 节点图的数据互通，
  文档提到自定义变量/局内存档 ✓ 但没查到确切的跨系统读写方式 ✓ —— 按规矩不编 ✓）。
  如果以后想"必须打完 10 关才算通关" ✓，我再去查 `局内存档.md` + 自定义变量那几篇 ✓。

### 一句话总结

> **想让"不能速通"成立，就不要把通关权交给玩家（退出按钮）或脚本，而是交给"节点图 + 240 秒计时"** ✓
> 这是平台自己认可的正规写法 ✓，也顺带满足"满 4 分钟才结算" ✓。

## 六、★ 需要什么节点图（节点名已从官方文档核实 ✓）

### 6.1 结论：**只要一张节点图、4 个节点**（挂在**关卡实体**上）

| 顺序 | 节点名（官方） | 设置 | 依据 |
|---|---|---|---|
| ① 入口 | **实体创建时**（事件节点） | 挂在**关卡实体**上 —— 官方："关卡实体、角色实体和玩家实体会**在进入关卡时触发**该事件" | `mhn7ko01v3yw_事件节点.md` |
| ② 启动 | **启动定时器**（执行节点） | 目标实体=关卡实体；**定时器名称**=例如 `结算门`；**定时器序列 = {240}**；是否循环=**否** | `mhufb90zbnts_定时器.md` |
| ③ 到点 | **定时器触发时**（事件节点） | 收到"序列序号 = 1"（就是第 240 秒那一段） | 同上 |
| ④ 定状态 | **设置玩家结算成功状态** | = **胜利** | `mhx1du08nhwo_关卡结算.md` |
| ⑤ 结算 | **结算关卡** | 连接在 ④ 之后 | 同上 |

官方对定时器的原话（`定时器.md`）：

> **"定时器提供计时能力…只能通过节点图创建和使用。"**
> **"定时器序列应是一组从小到大排列的、以秒为单位的时间点（最小间隔 0.03 秒）……
> 定时器运行时，计时到达序列中的时间段，会向挂载该定时器的实体的节点图发送【定时器触发时】事件。"**

⇒ 我们只要 **一个时间点 `{240}`** ✓ —— 第 240 秒触发一次 ✓ 之后不循环 ✓。
⇒ **240 秒之前，「结算关卡」这条线根本不会被走到** ✓ ⇒ **无法速通** ✓✓

### 6.2 想在屏幕上显示"还剩多久"（可选 ✓，也不用改脚本）

| 组件 | 节点 | 说明 |
|---|---|---|
| **全局计时器**（预定义，倒计时 240 秒） | **以节点图执行节点激活计时器** | `mhawd6rl5kpy_全局计时器.md`："全局计时器有两种使用方式…**2. 节点图执行节点激活计时器**" |
| **计时器界面控件** | ——（配置里引用即可） | `mhnrdor7uyra_计时器界面控件.md`：类型选**倒计时**、来源实体选**关卡实体**、指定那个全局计时器 ⇒ 屏幕右上直接显示 `04:00` 倒计时 ✓ |

> ⚠ 注意区分两个东西（名字很像，作用不同 ✗）：
> - **定时器**（`定时器.md`）= 纯逻辑 ✓ **只能节点图创建** ✓ —— 用来**卡住结算** ✓
> - **全局计时器**（`全局计时器.md`）= 可**显示在界面上** ✓ —— 用来**给玩家看倒计时** ✓
> 两者可以只用前者 ✓（不给玩家看时间也完全能防速通 ✓）

### 6.3 还需要哪些节点？（我逐条排除过 ✓）

| 你可能以为要 | 实际要不要 | 为什么 |
|---|---|---|
| 初始化/开始节点 | ✅ 要（**实体创建时**）| 让定时器在关卡一开始就跑 ✓ |
| 计时节点 | ✅ 要（**启动定时器** + **定时器触发时**）| 防速通的核心 ✓ |
| 胜负判定节点 | ⭕ 可选（**设置玩家结算成功状态**）| 不设也能结算 ✓ 设了结算界面才分胜负 ✓ |
| 结算节点 | ✅ 要（**结算关卡**）| 唯一能"宣布通关"的东西 ✓ |
| 排行榜 / 段位节点 | ❌ **不要** | 那两个功能在**外围系统里都不开** ✓ 就没有节点可写 ✓ |
| 跟客户端脚本通信的节点 | ❌ **现在不需要** | 我们的彩蛋成绩**不参与结算** ✓（结算只认"满 4 分钟"✓）|
| 拦截退出按钮的节点 | ❌ **做不到** | 退出按钮是**固有界面控件**（不可移动/改尺寸）✓ 提前退只记**逃跑** ✓ 不算通关 ✓ |

### 6.4 落地清单（照着连就行 ✓）

1. 选**关卡实体** → 打开它的**节点图**
2. 从事件列表拖 **实体创建时**
3. 拖 **启动定时器**：序列填 `{240}`、名称填 `结算门`、不循环
4. 新建一段：**定时器触发时** → **设置玩家结算成功状态（胜利）** → **结算关卡**
5. （可选）加 **全局计时器**（倒计时 240 秒）+ 一个**计时器界面控件** ⇒ 屏幕上显示倒计时
6. 编辑器设置：`关卡设置 → 结算` = **个人结算**、**游戏内排名关**；**外围系统：排行榜/段位都不开**

⇒ 这样：**最快 4 分钟通关** ✓、**不上榜** ✓、**提前退只算逃跑** ✓、**玩家看得见倒计时** ✓。

## 七、节点图在哪创建、在哪挂（官方入口 ✓）

### 7.1 先"做"一张节点图 ⇒ 在 **千星沙箱** 里

官方 `节点图.md` 原文：

> **"在挂载前，需要先在千星沙箱中制作一张节点图。"**

入口（`整体界面.md` 里列的**系统菜单**功能里有这一项 ✓）：

    左上角【系统菜单】──►【打开千星沙箱】──► 在沙箱里新建一张节点图，连好逻辑、保存

### 7.2 再"挂"到实体上 ⇒ **实体/元件的详情编辑页 → 节点图页签**

官方 `节点图.md` 原文：

> **"实体节点图入口位于：实体或元件的详情编辑页-节点图配置页签**
>  **(1) 实体或元件编辑页面切换到节点图页签  (2) 点击新增节点图"**

我们要挂的对象是 **关卡实体** ✓（官方："在**关卡实体**上挂载节点图，用于实现一个**全局计分**的机制" ✓
—— 我们要的正是"全局的结算门" ✓ 所以挂关卡实体 ✓）。

### 7.3 节点图有 7 种，我们只用**实体节点图** ✓

| 类型 | 运行侧 | 我们用它吗 |
|---|---|---|
| **实体节点图** | **服务端** ✓ | ✅ **就用这个**（挂关卡实体 ✓ 结算必须服务端 ✓）|
| 单位状态 / 职业 / 道具 节点图 | 服务端 | ❌ 不用 |
| 技能 / 造物状态 / 本地过滤器 节点图 | 客户端 | ❌ 不用（客户端节点图管不了结算 ✗）|

> 官方："其中**实体节点图**、单位状态节点图、职业节点图和道具节点图的逻辑**在服务端运行**，
> 因此统称为**服务端节点图**" ✓ —— 而结算属于服务端行为 ✓ 所以必须是实体节点图 ✓。

### 7.4 三步走（照做 ✓）

1. 【系统菜单】→【打开千星沙箱】→ 新建节点图：连
   `实体创建时 → 启动定时器{240} → （定时器触发时）→ 设置玩家结算成功状态 → 结算关卡`
2. 回到场景，选中**关卡实体** → 详情编辑页 → **节点图**页签 → **新增节点图** → 选刚做的那张
3. 编辑器设置：`关卡设置 → 结算` = 个人结算 + 游戏内排名关；`外围系统`：排行榜/段位都不开 ✓
