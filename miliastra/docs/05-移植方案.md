## 1. 一句话

**本作在千星奇域里的形态 = 一张客户端控件画布 + 一段 Lua 客户端脚本。**
不建场景实体、不用基础运动器、不用服务端节点图。官方原话：

> 「**客户端脚本可以实现绝大多数 2D 玩法**，以及界面的动态效果」——`mhbgxf0nynww`

---

## 2. 目标形态

```
客户端控件容器（画布）
├── 玩区容器（铺满画布、以画布中心为原点）
│   ├── 球池：N 个图片控件        ← 运行期只改 位置/尺寸/颜色/图片/可见性
│   ├── 弹药池：M 个图片控件
│   ├── HUD：6 个文本框（分数/命/连读/模式/提示/结算）
│   └── 光标检测区域：1 个 CursorEventArea（铺满画布）
Lua 脚本（挂在画布容器上）
  OnUpdate(dt): input.update -> board.advanceScene -> ui.sync
```

**关键取舍**：球**不是实体**，是图片控件。所以"每颗球"没有 GUID、没有受击盒、
没有运动器 —— 全部状态在 Lua 的表里，碰撞就是纯数学。这一条同时消掉了
`docs/04` 里一半的硬约束。

### 4.1 移植时踩到的真问题（"看起来能照抄，其实不能"）

1. **JS 的函数是对象，Lua 的不是。** `rng` 有 `.int`/`.pick`，`crossReturnSpine` 返回的函数挂
   `.junctionU`；Lua 里 `fn.field = x` 直接报错。解法：统一用**可调用的表**（`__call`），
   调用点写法与 JS 完全相同。
2. **`Math.imul`/`>>>`/`|0` 没有对应物。** Lua 5.3 整数是 64 位，两个 32 位数直接相乘会溢出
   64 位 → 拆成 16 位半字相乘。写错的话**随机数全错但不报错**。
3. **下标基号不同。** JS 0 基 / Lua 1 基，且 `chain.balls` 有"第 0 个 = 洞端"的语义。
   ★ 真咬人：`pushBack` 的"贴洞端就不退"在 JS 是 `headEnd <= 0`，1 基写成 `<= 1` 才对；
   差一位导致**爆炸后的后退整条路径对不上**，靠 `tools/parity-diff.mjs` 定位。
4. **JS 的 NaN 会安静跳过，Lua 的 nil 会报错。** 本帧刚冒出来还没同步坐标的球，
   JS 里 `x` 是 undefined → NaN → 弹丸自然穿过；Lua 里必须显式判空。
5. **随机数消耗次序是契约的一部分。** `advanceScene` 里那句恒为假的
   `rng() < DESIGN.baseRepeat` **仍然消耗一次抽样**；漏掉它整条随机序列就错位。
   （这也暴露了本体的一处悬空引用，见 §11。）

## 5. 渲染映射（render.js → 客户端控件）

| 本体画的东西 | 千星奇域里怎么做 |
|---|---|
| 球 | `ClientUIImageControl`：`SetImage` + `anchoredPositionX/Y` + `sizeDeltaX/Y` |
| 球色（5 碱基 / 错误灰） | `imageColor` 读写 —— **一张图染 5 色，不需要 5 张素材** |
| 文字（分数/徽章/提示） | `ClientUITextBoxControl.text`（读写，运行时刷新） |
| 洞（吸入进度） | `SetFillRadial360` / `fillAmount` |
| 消除/爆炸动效 | `game.Tween`（30 种缓动）/ `TweenSequence` |
| 轨道形状 | 编辑期摆好的静态图片；形状来自 `out/path-<id>.svg` |

**坐标换算**（唯一一处容易搞错的地方）：board 用"画布像素、原点左上、y 向下"，
控件用"相对父级中心、y 向上"，所以 `uiY = view.cy - y`、
`cursorBoardY = canvas.h - cursorUIY`。两处换算都写成了具名函数并有断言。

## 7. 平台限制 vs 我们的用量

| 项 | 上限 | 我们用 | 余量 |
|---|---|---|---|
| 单个界面控件组内控件 | 1000 | 1 根 + 1 玩区 + 1 光标区 + 32 球 + 4 弹药 + 6 HUD = **45** | 22× |
| 单次屏幕内可显示控件 | 10000 | 同上 | 222× |
| 自定义控件模板 | 2000 | 4（球/文本框/光标区/玩区） | 500× |
| 界面布局 | 100 | 1 | 100× |

**仍有约束**（写在代码里，不只在文档里）：

1. `lua/src/` 不许用 `io.*` / `coroutine.*` / `string.dump` / 大部分 `os.*` `debug.*`
   → `tools/check-lua-sandbox.mjs` 自动拦。**本地跑得通不代表上传跑得通**。
   （`print`/`printerr` 是官方日志 API，不在禁列。）
2. 动态创建控件有坑（主屏控件、模板控件子节点都不能动态创建）→ 代码里 `game.lua` 把
   池子建在**玩区容器**下，且**运行期只改属性不新建/销毁**控件。
3. 只有**建过脚本映射**的 lua 才会被打包上传。
4. 联机信号延迟最低 100ms → **只做单人**。

## 8. 验证策略（四层，缺一不可）

### 第一层：JS↔Lua 对拍 —— 移植正确性的唯一证据

```
node miliastra/tools/parity.mjs          # 308 条命令 -> 5702 行 / 81339 个数值
node miliastra/tools/parity-diff.mjs <命令文件>   # 失败时定位第一处分叉
```

场景只写一次：命令表由 `tools/parity.mjs` 生成，JS 侧（`tools/lib/parity-js.mjs`）与
Lua 侧（`lua/parity/run.lua`）各写一个解释器执行同一份。最难的一块是 `board`：
**整局对拍** —— 机器人按确定性随机瞄准开火，每帧比对球数/分数/命/统计/每颗球的状态。

### 第二层：Lua 沙箱检查

```
node miliastra/tools/check-lua-sandbox.mjs     # 14 个文件 / 2618 行 0 问题
```

### 第三层：Lua 侧测试（**假宿主**）

```
node miliastra/tools/test-lua.mjs        # 75 项断言
```

`lua/host/mock.lua` 照官方 API 实现了 `game.*` / 控件对象 / Tween / Enum / 脚本生命周期，
并把它们装成**全局** —— 所以 `ui.lua`/`input.lua`/`game.lua` 里写的就是
`game.GetCursorUIPos()`、`Enum.CursorEventType.CursorClick`，**没有任何"为了测试而做的适配层"**。
三个测试文件分别验证：假宿主本身（32 项）、表现层+输入层+整关（24 项）、
**打包产物**（19 项）。

### 第三层半：全关卡巡检（移植侧的 probe-play）

    node miliastra/tools/test-lua.mjs test_levels.lua    # 58 项断言

11 个关卡逐个装配 + 让机器人打，检查：装配不报错 / 有轨道 / 提示文案不超 1000 字符 /
控件数不超上限 / 静止练习关机器人必过。跑出来一张表（结果、原因、帧数、球数、分数、命、控件数）——
这张表直接暴露了 §11 里那条**本体侧的盘面无解**问题。

### 第四层：打包产物端到端

`test_bundle.lua` 直接 `loadfile('out/zuma.lua')`，然后**像运行时那样**调用全局
`OnInit()`/`OnUpdate(dt)`，把 ① 配对关打通。它证明的是"**要上传的那个文件**本身能跑"，
而不只是"源码能跑"。

### 第五层：本体回归

移植**不许**动 `src/`。每次改完跑一遍本体的 546 个测试（本轮实测全绿）。

### 参考解释器怎么来的

```
bash miliastra/tools/build-lua.sh     # 从 lua.org 拉 Lua 5.3.6 源码编译 -> vendor/bin/lua
```

**环境坑**：`/storage` 是 **noexec** 挂载，编译出来的 lua 直接执行会 Permission denied，
所以 runner 会先把二进制拷到 `$TMPDIR` 再跑（`tools/lib/lua-runner.mjs`）。

## 9. 打包与上传流程

```
node miliastra/tools/bundle-lua.mjs     # lua/src/*.lua -> out/zuma.lua（14 模块，86 KB）
```

打包器把每个模块包成 `__M["名"] = function() ... end`，顶部放**局部 `require` 覆盖**，
最后把 `game` 模块的 7 个生命周期回调**暴露成全局**
（官方："运行时按固定名称查找并调用"）。

编辑器里要做的事：

1. 客户端脚本资源管理器 → 新建客户端脚本 → 把 `out/zuma.lua` 的内容写进去
   （**必须建立脚本映射**，否则不会被打包上传）；
2. 建一个**客户端控件容器画布**；
3. 建 4 个客户端控件模板：图片（球）、文本框、光标检测区域、玩区容器；
4. 在容器的**脚本页签**里挂上脚本；
5. 填脚本变量：`levelIndex` / `ballPrefab` / `shotPrefab` / `hudPrefab` /
   `cursorPrefab` / `playPrefab` / `ballCount` / `shotCount` / `seed` / `autoNext`；
6. 试玩。

## 11. 还没做 / 没证实 / 给本体的两条待办

**移植侧**

1. **编辑器里没搭过** —— 一切"能不能跑"的结论都来自无头假宿主，真机未验证。
2. **`OnUpdate` 实际帧率未知**；**45 个控件同帧改属性的性能未知**。
3. **`InstantiateClientUIControl` 的真实边界未实测** —— 代码依赖它建池子；
   若在编辑器里不可用，退路是"编辑期摆好控件 + 用脚本变量逐个取运行时 ID"。
4. **脚本变量 `script:GetParam` 的可用类型未实测**（代码只用到整数）。
5. 七球模式（元素反应）没有移植；选关菜单、音效、模式按钮还没做。

**本体侧（移植过程中发现，本轮**没有**改动 `src/`）**

1. ★ `src/scene.js:737` 引用了 `DESIGN.baseRepeat`，但该常量已从 `src/config.js` 删除
   → 条件恒假。当前行为恰好是想要的（永远换碱基），但这是一条会误导后来人的悬空引用；
   要么补回 `baseRepeat: 0.7` 并实测，要么把那行改成"恒定换碱基"。
   ⚠ 注意它**仍然消耗一次随机抽样**，删除时必须保留这次消耗，否则整条随机序列改变。
2. ★ **`startWpFrac` 会留下一个大空隙**（t6 洞穴关实测）：`assembleScene` 把整条链平移到
   0.72×轨道长之后，**冒球口（wp=0）到队尾之间有 400+ 单位是空的**。于是新冒出来的球
   要花 ~1700 帧（28 秒）才能追上队尾、把推动传导到队头 —— 玩家看到的是
   **"链子先僵住 28 秒，然后突然开始爬"**，与关卡说明"它现在离洞口很近"的意图相悖。
   移植侧**照抄了这个行为**（对拍证明两边一致），所以这是本体要决定的事：
   要么冒球口跟着队尾走，要么 `startWpFrac` 改成"整链平移但队尾不越过冒球口"。
3. ★★ **存在合法但无解的盘面**（全关卡巡检实测：11 关里有 6 关会被卡住）。
   形态：**链首那颗是 mark=2**，标记序列形如 211 / 221，而剩余 run 长度又不是 3 的倍数。
   根因是 run.js 的爆炸规则**本身**：链首/链尾的 2「缺一侧真邻居 -> 待定」，
   注释里写明了设计意图是「**等冒球把它顶出边界再判**」。
   可这条规则隐含假设「链子会一直冒球」—— 限球关卡**预算发满之后就不再冒球**，假设失效，
   于是那两颗 2 永远不爆、剩下的 1 又凑不满 3 颗，玩家只能重开。
   建议三选一：① 预算发满且盘面无解时自动补球（宽容）；② 加无解检测自动重开并提示；
   ③ 改成「链首/链尾的 2 在预算耗尽后按缺邻居视为 0 判爆」（改动核心规则，需重新平衡）。
   移植侧**照抄了本体行为**（对拍证明两边一致），所以这条要回本体侧决定。
4. `settle()` 用全局 `DESIGN.winOnClear` 而非关卡字段，探针需要关掉它只能改全局常量 ——
   建议加 `level.winOnClear`（移植侧已按全局常量对齐）。
