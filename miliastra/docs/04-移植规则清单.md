# 移植规则清单（跨平台）

这份是**要照着重写的逻辑本身**，和"用节点图怎么实现"分开写（后者见 docs/04）。
写它的理由：**规则一旦被翻译成节点图，就很难再看出它和本体的差异了** ——
所以先把规则用平台无关的方式钉下来，移植完再逐条对照。

**本体就是参考实现**：`../src/run.js`（标记与成段）、`../src/scene.js`（结算顺序）、
`../src/chain.js`（珠串）。有歧义时以代码为准，不是以这份文档为准。

---

## 1. 每颗球的状态

```
base    碱基：A / U / G / C / T       （决定"该发什么"）
mark    标记：0 未读 / 1 配对 / 2 配错
dock    吸附飞行的进度 0~1（0.30 秒飞完；只有 dock>=1 才计入成段）
slot    槽位号（移植版新增；本体是弧长 wp）
id      唯一标识
```

⚠ `dock` 这一条**很容易漏**：小球要飞 0.30 秒才落位，所以"连打几发"时
它们会**几乎同时落位**，成段长度可能从 0 直接跳到 4 ✓
（本体上这个特性制造过死局，见 DESIGN.md §63.3 —— 练习关的球数必须是 3 的倍数就是这个原因。）

## 2. 配对表（不对称）

```
A <- U 或 T        （A 是唯一的双配碱基）
U <- A
T <- A
G <- C
C <- G
```

**必须照抄这个不对称**。写成"A 配 U/T、U 配 A、T 配 A"就对了，
写成对称表（A-U 互相、G-C 互相）在 `T` 上会错 ✓

## 3. 一次命中的分流（只有两条路）

```
珠子.碱基 与 球.碱基 互补  ->  配对：mark = 1，进入吸附飞行
否则                      ->  配错：mark = 2，进入吸附飞行
```

**没有第三条路** ✓ 不扣分（这是用户明确要求的设计：配对错误不带来负反馈，
代价通过爆炸间接体现）✓

## 4. 成段（run）与消除

```
run  = 序列上**连续的 mark==1 且 dock>=1** 的段
若 run.长度 >= 3 且 run.长度 % 3 == 0  ->  整段移除（消除）
```

关键点：
- **4 颗、5 颗不消** —— 必须是 3 的倍数。这是"最反直觉"的一条，
  本体为此在球旁边挂了「N 颗 · 还差 M」的徽章（§24）。
- run 只看**序列相邻**，与物理空隙无关（§19）。
- 消除后，后面那些球的槽位号要**往前挪 run.长度 格**（本体的"回缩"离散版）。

## 5. 爆炸（错误配对的后果）

```
一颗 mark==2 的球，当且仅当：
  ① 它左右两颗都已经读出（mark != 0），且
  ② 这两颗**状态相同**（都是 1，或都是 2）
-> 连它自己一起移除 3 颗（它 + 左 + 右）
```

关键点：
- **不是"一打错就炸"** ✓ 条件不满足时它就静静躺着（用户明确要求把这句写在提示里）。
- 边界上的 2（在队首或队尾）**永远不会炸** —— 它凑不齐两个邻居（§31）。
- 移除永远是 **3 颗**，所以"所有移除都是 3 的倍数"这条不变量不会被破坏（§30）。

## 6. 结算顺序（**重要**）

```
每一帧：先爆炸，后 3n 消，然后再看有没有新的爆炸/消除 —— 循环到不动点
爆炸一次只处理一个，从左到右扫
```

顺序不能反 ✓ 反了的话 `1 2 1 2 1` 这类重叠局面会有两种结果（§32）。

## 7. 珠子袋（决定"手里该发什么"）

```
候选池 = 场上**未配对**球的互补碱基，**按球数加权、不去重**
         （场上有 3 颗 A，池子里就有 3 个 U）
另外：手里已有的珠子若"场上已经没有它能配的球"，就重抽一颗能配的
```

这一条看着不起眼，但它是**平衡的命门**（§54）：
不做"过期刷新"时，本体实测 **85.7% 的帧手里没有可打的目标**，清球速度跟不上冒球，必输 ✓

## 8. 过关与失败

```
过关（三选一，按关卡配置）：
  clear  —— 球数预算发满 + 场上清空（有限球数关）
  score  —— 分数达标（无尽关）
  match  —— 把每一颗都读出来（练习关，且该关 noClear：不消球也不爆炸）

失败：队头到达洞穴 -> 扣 1 命 -> 命未尽则重开本关（场上重新铺球），命尽则 GameOver
      —— 静止练习关**没有洞穴**，也就没有失败
```

## 9. 静止练习关（移植时不要做错）

①~⑤ 关是静止练习：**不出球、不前进、没有洞穴、不会输**，目标是把球清光或读光 ✓

两条硬约束（都是踩坑换来的）：
1. **会消球的练习关，场上球数必须是 3 的倍数** —— 否则"同时落位"会造出 3n+1，永久死局（§63.3）。
2. **静止 ≠ 跳过推进** —— 插球要靠"绳模型的顶开"，跳过推进会让插进去的球叠住（§65.3）。
   移植版对应的是：槽位号的插入/挪动必须自己实现。

## 10. 不要移植的东西

- **七球（元素）模式**：代码还在，但已移出玩家可见的模式循环（§65）。移植时不要做。
- **穿隙计分 / 连击倍率 / 难度爬升 / 减速带**：都是 §12-B 的冻结项，从未实现。
- **渲染细节**：配色、粒子、屏震 —— 千星奇域用平台自己的表现。

## 11. 移植后必须回测的数值

用 `tools/calc-balance.mjs` 算，判据来自本体实测：
- 冒球率 = 速度 / 球距，**必须 ≤ 1.6 颗/秒**（本体实测清球率上限 1.23~1.55）
- 槽位数 = 轨道长 / 球距，**必须 ≥ 球数预算**
- 时限 = 轨道长 / 速度 —— 这是玩家什么都不做时能撑多久
