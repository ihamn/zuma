## 1. 命中检测

- 组件功能：「命中检测组件可以在组件内定义的命中区域碰到其他实体或场景地形（以及水面）时，向服务端节点图发送命中事件」——可当投射物攻击盒用。
- 事件节点【命中检测触发时】出参：事件源实体 / 事件源GUID / 是否命中受击盒 / **命中实体** / 命中位置。
- **能拿到被碰到的对象**，但有条件：「仅当命中受击盒时，命中实体才有意义」；「命中实体受击盒时，返回命中的实体。命中场景或自身碰撞时，返回空」。
- 触发类型：单次触发 / 不重复触发 / 重复触发（受触发间隔限制）。检测延迟时间用于「防止投射物类的物件在射出时命中发射者自身」。
- 形状：长方体、球体、胶囊体；可配多个触发区叠加。
- CCD：「检测半径…当值为0时，使用射线进行检测」；可设速度阈值只对高速投射物开启。
- 筛选：阵营筛选、实体类型筛选（物件/角色/造物）、命中层筛选（受击盒/场景/物件自身碰撞）。过滤器节点图输出「获取自身实体＝投射物实体、获取目标实体＝命中的实体」。
- **能否判断"第几个"：文档完全没有这类节点或概念。** 只能拿到实体本身。
- 独立射线检测节点：查询节点【获取射线检测结果】——「会根据射线命中从近到远的顺序返回满足筛选条件的第一个目标或命中位置」，入参含阵营筛选、实体类型筛选。只给第一个。
- 球体检测：查询节点【筛选球体范围内的实体列表】——「以特定的规则和数量上限筛选在球形范围内的实体，满足条件的实体会组成实体列表输出」，筛选规则枚举为「默认排序、随机排序、从近到远排序」。这是主动查询，不是命中事件。

## 2. 碰撞触发器

- 成对机制：碰撞触发器（检测方）+ 碰撞触发源（被检测方）。「关卡运行中，'碰撞触发器'持续监测其他携带'碰撞触发源组件'的实体」，两者的生效范围相交即向触发器持有者发事件。「这种碰撞并不会带来物理层的碰撞阻碍」。
- 触发器可同时多个；触发源「仅可同时生效一个」。多个触发器对同一触发源「分别发送节点图事件，互不影响」。
- 配置：生效目标（角色/物件/造物枚举）；触发区形状长方体/球体/胶囊体；「同一碰撞触发器下的范围会取并集范围生效」。
- 事件出参【进入/离开碰撞触发器时】：进入者实体、进入者实体GUID、触发器实体、触发器实体GUID、**触发器序号**。
- **一组同类物体能否共用一个触发器**：文档只给了「一个范围可同时容纳多个实体」+节点【获取碰撞触发器内所有实体】（入参 目标实体、触发器序号 → 出参 实体列表），可用它做批量枚举。文档**没有**写"把一组物体统一绑定到一个触发器"的配置方式。
- 上限：「碰撞触发器范围内的实体数量上限 100。使用获取范围内实体列表的时候只能拿到最早进入的 100 个实体，另外达上限后不会触发进入碰撞触发器时的事件」（编辑项范围限制）。
- 附带规则：「造物、角色实体，默认包含碰撞触发源，无需额外编辑」；不含触发源的实体「无法通过接触碰撞触发器产生事件」。

## 3. 扫描标签（重要纠正）

- 扫描标签**不是**通用的"按标签批量查物体"系统。「扫描功能是指玩家在游玩关卡时，可以通过操作镜头来选取某一个实体的功能」，配合扫描组件用于技能瞄准。
- 关键限制：「同一时刻处于扫描标签激活状态的实体是唯一的」——给不了"一组"。
- 客户端节点【获取扫描组件可扫描的所有合法对象】能拿列表，但那是镜头扫描候选，受障碍检测/距离检测/视线检测/视野范围约束，还有职业属性"扫描标签识别规则"（视野中心距离 / 实际位置距离）决定唯一激活者。
- **真正能按标签批量查询的是"单位标签"**：「可以使用单位标签快速定位到所有带有该标签的单位」，节点【获取单位标签的实体列表】——「获取在场所有携带该单位标签的实体列表」，入参 单位标签索引（整数），出参 实体列表。还有【获取实体单位标签列表】。
- 拿到的是列表吗：是，实体列表。
- 能排序吗：**实体列表不能排序**。【列表排序】节点明确只支持「整数列表或浮点数列表」。实体列表唯一相关的"排序"是球体/方形范围查询的"从近到远排序"筛选规则。

## 4. 结构体

- 「结构体是一种允许创作者将一组不同类型的数据整合在一起，形成一个自定义数据的高级数据结构」，**在服务端节点图中使用**。
- 成员可用的类型含全部基础类型 + 列表类型 + 所有字典 + 自定义结构体，「结构体内部是可以继续使用结构体以及结构体列表的（即支持结构体嵌套）」。
- **可以存数组**：明确列出"实体列表 / 整数列表 / 字符串列表 / 自定义结构体列表"等。
- 节点图读写：运算节点【拼装结构体】【拆分结构体】、执行节点【修改结构体】（可勾选只改部分成员）。使用前须用泛型按钮选定具体结构体。
- 引用传递：「结构体在节点图中也是以引用的方式进行传递」，修改「不会触发【自定义变量变化时】事件，需要通过【获取自定义变量】节点来获取变化后的值」。
- 类型由名字完全确定，「不同名的结构体即使内部的数据结构相同，也是不同的结构体，在节点图中不能相连」。
- 可用于 服务端节点图 / 自定义变量 / 节点图变量。自定义变量支持 整数/浮点数/字符串/布尔值/三维向量/**实体**/GUID/元件ID/配置ID/结构体 及各自的列表 + 所有字典类型。

## 5. 计分板 / 界面控件

- 计分板界面控件：「关卡运行时，用于显示玩家自定义变量，并可以根据自定义变量进行排名的信息展示界面」。可配排序（数值升序/降序）、类型（个人/阵营）；个人可显示 名次/分数/阵营图标/玩家名称/玩家头像。**它是玩家维度的排名板，不能显示任意文本，也不是给单个数字用的。**
- 文本框界面控件：「显示预先编辑的文本内容。若文本内容中，包含自定义变量，会实时更新显示」。富文本格式 `{类型:前缀.变量名}`，类型填 1 表示引用自定义变量，前缀 p1~8（玩家）/ lv（关卡实体）/ ps（玩家自身实体），例：`{1:p4.测试2}`。「插入的自定义变量数据变化后，运行中显示的文本内容会进行更新」——**可动态刷新**。
- 特殊数字控件数据来源只有 技能/道具/单位状态（冷却、层数等），不适合自定义积分。
- 案例里的做法：4.1.3 用【全局计时器】+计时器控件显示倒计时，结算时用【列表循环迭代】+【切换当前界面布局】切到独立的"界面布局"展示计分板。

- 总览 mhzi4r003o0g_4.1派对小游戏：《农场乱斗》.md

玩法：「方形的农场内，玩家在规定时间里，通过开垦、播种、采集等行为进行种植，并收获成熟的果实，将果实上交给商店获得积分，游戏结束后积分最高者获胜」。俯视角、2~4人各1队、5min/局。特色机制为资源博弈（偷工具）与偷菜。

**实体清单**：土地（空物件，挂自定义变量"土地等级"整数 0=未开垦→1 已开垦→2 已播种→3 已浇水，升级效果用"创建元件/特效"表现）、工具（耙子/种子/水壶，挂【选项卡】含"拾取"与"切换"两个选项）、种植物（幼苗期/生长期/成熟期三个元件，成熟期加循环特效）、果实商（挂【碰撞触发器】）、准备台/准备物件（选项卡）、玩家、角色、关卡实体。

**节点图挂载点**（官方逐条列出"该节点图挂载对象为：【X】"）：各个工具、玩家、角色、土地、果实商、准备台、关卡。

**用到的数据（全部自定义变量）**：玩家上——"是否有工具"、"装备的工具是"、"种子可使用次数"、"可操作的土地是"（类型：实体）、"当前采集数量"、"积分值"、"装饰物工具"、采集物实体列表（类型：实体列表）；土地上——"土地等级"、"是否可采集"（布尔）、旧种植物（类型：实体）；种子上——"可使用次数"（初始 5）；关卡上——"局内玩家总人数"、"当前已准备玩家数"。

**事件节点**：选项卡选中时、进入/离开碰撞触发器时、自定义变量变化时、定时器触发时、技能节点调用时（监听客户端节点【通知服务器节点图】）、实体创建时、全局计时器触发时。

**数据流转（原文摘要）**：
1. 拾取工具 → 写玩家变量"是否有工具/装备的工具"→ 给**角色**添加工具技能（"技能是添加给【角色】而非【玩家】"）。
2. 客户端技能节点图**只发信号**：「由于本地技能不具备直接操作效果，因此仅发送使用技能信号，转由服务器节点图制作」。
3. 玩家进入土地碰撞触发器 → 把这块土地实体**存进玩家的实体型自定义变量**"可操作的土地是"；离开时设为空值。
4. 使用工具 → 多分支判断工具 + 判断土地等级（禁止跳级）→ 创建元件表现升级 → 土地等级 +1。
5. 土地变量变化 → 启动定时器（序列 2、4、6 秒）→ 每次「销毁实体」旧的 + 「创建元件」新的来表现生长 → 成熟期设"是否可采集=是"。
6. 玩家进入果实商触发器 → 积分公式「新积分值 = 旧积分值 + 上交采集物数量 × 10」→ 清空果实数。
7. 阵营隔离：「判断玩家是否可操作土地格时，仅同阵营土地格可操作」。
8. 准备流程：玩家出生在准备区预设点，玩家变量"是否已准备" + 关卡变量"已准备人数/总人数"相等 → 【列表循环迭代】+【传送玩家】送入游戏区 → 启动 5 分钟全局计时器 → 到点传送回准备区并展示计分板。

**UI 做法**：文本框插入【玩家自身】变量显示 装备工具/种子可用次数/采集果实数/积分值（4.1.2 明确列出这四项）；4.1.1 正文反复标注"教程为了方便演示增加了 UI 显示…（此处暂不拓展，会在后续课程进行讲解）"。手持道具表现用【跟随运动器】+ 挂接点 "RHand"。
4.1.2 里唯一一处"批量销毁"范例：玩家用**实体列表**型自定义变量记录跟随的采集装饰物，上交时「使用【列表循环迭代】+【销毁实体】移除玩家记录的采集物实体」，循环结束后【清除列表】。

## 7. 对照祖玛核心问题

- 「子弹打中某颗球 → 得知打中了哪个实体」：**文档支持**。命中检测的"命中实体"出参 + 球上必须有**受击盒**（否则"命中实体"返回空）。
- 「得知打中了第几颗」：**文档没有直接支持**，必须自建。文档里可用的两条线索：
  - (A) 每颗球挂一个整数自定义变量记自己的位置/序号，命中后用查询节点【获取自定义变量】配合"命中实体"读出该值。
  - (B) 用【获取单位标签的实体列表】（或【获取场上指定元件ID的实体】/【筛选球体范围内的实体列表】）得到球实体列表，再用【查找列表并返回值的序号】——「从列表中查找指定值，并返回列表中该值出现的序号列表」，把"命中实体"当值查下标。
- 「按规则消除一段」：文档没有"一段/连续匹配"的任何概念，需自行用列表迭代+条件判断实现。批量销毁可照 4.1.2 的【列表循环迭代】+【销毁实体】模式。
